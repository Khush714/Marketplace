# AGENTS.md

Guidance for AI coding agents working in this repository. Human contributors can
follow it too. Architecture is documented in `docs/`; read it before making
non-trivial changes.

## What this is

A **Next.js 16 App Router** marketplace that sits between diners and restaurant
POS systems. Orders and payments flow through it; fulfilment lives in the POS.
No customer accounts. **PostgreSQL** (Drizzle ORM, plain-SQL migrations) is the
only state store. **Razorpay** is the payment provider.

Start here:
- `docs/system-design.md` — what the system is and why (actors, workflows, tenancy, sensitivity).
- `docs/architecture.md` — how it is built (layers, runtime topology, flows, known gaps).
- `docs/decisions/` — ADRs explaining why things are the way they are (0001–0006).
- `docs/baseline/` — frozen Phase 0 baseline, gate results, route/table inventory.

## Commands

| Task | Command |
|---|---|
| Dev server | `npm run dev` |
| Typecheck | `npm run typecheck` (`tsc --noEmit`) |
| Lint | `npm run lint` (`eslint .`) |
| Unit tests | `npm run test:unit` |
| Security E2E | `npm run test:security` |
| All tests | `npm test` |
| Everything | `npm run verify` (typecheck + lint + test) |
| Build | `npm run build` |
| Migrate DB | `npm run db:migrate` (needs `MIGRATIONS_DATABASE_URL`) |
| Seed / reset | `npm run db:seed` / `npm run db:reset` (both require `--confirm`) |

The **security E2E suite needs a reachable PostgreSQL** and runs `next start`.
If Postgres is unavailable it is skipped locally but **fails closed in CI**
(`REQUIRE_SECURITY_TESTS=1`). Default local DB: `postgres/postgres@127.0.0.1:5432`.

## Non-negotiable rules

1. **Run `npm run verify` before declaring a change done.** Money, auth and
   delivery paths also warrant `npm run test:security`.
2. **Never trust the browser with money or order state.** A payment becomes
   `PAID` only on signature-verified provider evidence. Order access requires the
   signed order token or a bound customer session. Never add a path that lets a
   client assert success.
3. **Fail closed.** A missing secret/token/config must deny, not open. See
   `lib/ops-auth.ts`, `lib/cron-auth-core.ts`, `lib/ordering-gate.ts`,
   `integrations/payments/provider-session.ts`.
4. **Keep `*-core.ts` pure.** Policy that needs unit testing goes in a
   dependency-free `*-core.ts` (no `server-only`, no DB, no network); the server
   wiring lives beside it. Follow the existing pattern.
5. **Secrets never reach logs.** Emit through `lib/security/security-events.ts`;
   redaction is central (`security-events-core.ts`). Never `console.log` a
   credential, token, key or full address.
6. **Hash credentials at rest; compare in constant time** (`lib/owner-key.ts`,
   `timingSafeEqual`).
7. **Durability before delivery.** Persist a journal row before any POS/payment
   HTTP call; make consumers idempotent on a stable id.
8. **Scope every query by `restaurant_id`.** Tenancy is restaurant-scoped; a
   missing scope is a cross-tenant leak.
9. **Do not edit the baseline.** `docs/baseline/*` is a frozen snapshot; treat it
   as historical, not as live documentation to update.
10. **Match existing conventions.** No comments unless they explain *why* (this
    codebase has a strong "why in the comment" style). No new libraries without
    checking `package.json` — the dependency set is deliberately small.

## Conventions and gotchas

- **Money** is integer paise in columns ending `_cents`; a `real` rupee mirror
  exists only for POS parity. Never do float money.
- **POS ids are `bigint`** (epoch-ms overflows int4). Keep `mode: "number"` when
  touching Drizzle bigint columns.
- **Idempotency keys are load-bearing:** `orders.client_request_id`,
  `mkt_ord_<id>` external order id, `<reference>:<eventType>` bridge event ids,
  and every webhook `event_id` ledger. Do not change their shape unilaterally.
- **Capped bodies only:** use `readJsonBody` / `readRawBodyCapped` from
  `lib/abuse.ts`, not `req.json()`.
- **Guards before work:** mutating routes call `guardWrite(scope)`; reads call
  `guardRead(scope)`. Add a budget in `abuse-core.ts` for any new public route.
- **PowerShell environment (Windows):** `rg` is not on `PATH`; redirection to
  temp files can fail with EPERM. Prefer the editor/agent file tools over shell
  text processing.
- **Migrations are hand-written SQL** in `src/db/migrations/`, not generated by
  `db:push` for production. Follow the dated filename convention and update
  `src/db/schema.ts` in step.

## Known gaps (do not mistake for current behaviour)

See `docs/architecture.md` §12. Highlights: the customer-session read path is not
fully wired (`lib/order-authorized.ts` is unused; cancel route lacks `guardWrite`);
`lib/security/integration-auth.ts` is dead code; 9 high dependency advisories;
the least-privilege DB role is unused; per-instance rate limits.

## Committing

Only commit when explicitly asked. Stage only intended files; run `git status`
and `git diff` first. Do not commit `.env` files or secrets.
